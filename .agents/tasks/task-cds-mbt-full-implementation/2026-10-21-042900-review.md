## High-level view

The core engine (`lib/core/`) provides systematic path exploration through XState machines with invariant checking at each step. The `runMBT()` function is the main entry point, returning detailed results including paths, violations, and statistics. Eight built-in invariants cover common agent concerns (budget, retries, completion validity, escalation reasons).

The Joule integration (`lib/joule/`) offers four pre-built machine templates: ReAct loops for LLM agents, A2A protocol for agent-to-agent communication, HITL for human-approval workflows, and subagent coordination for parallel task decomposition. The `RuntimeAdapter` class enables live validation of running agents through state change monitoring.

The TLA+ export (`lib/tla/`) generates valid TLA+ specifications from XState machines, translating states to constants, transitions to actions, and MBT invariants to TLA+ formulas. The `TLCRunner` class handles model checker execution with graceful fallback when TLC isn't installed.

CLI commands (`cds mbt init`, `run`, `extract`, `export`, `watch`) integrate with the CDS plugin system. Three complete examples demonstrate migration ETL, ReAct order agents, and multi-step approval workflows.

## Core MBT engine

The path explorer uses breadth-first state exploration with loop detection. It creates fresh XState actors for each transition attempt, preventing state mutation across exploration branches. The `checkInvariants()` function evaluates each invariant at every step, collecting violations with full context (state, context snapshot, path trace).

The invariant builder supports composable patterns: `createInvariant()` for custom checks, `fromPredicate()` for simple boolean conditions, `combine()` for aggregation, `when()` for conditional application, and `bound()` for numeric comparisons. Built-in invariants handle the common failure modes: `budgetRespected` prevents runaway LLM costs, `retriesBounded` caps per-tool retries, `noInvalidCompletion` ensures required tools succeeded before completion, `escalationHasReason` guarantees actionable error context.

## Joule machine templates

`createReActMachine()` models the observe→think→act cycle with configurable iteration limits and LLM budget. Guards prevent infinite loops by checking `maxIterations` and `budgetExhausted` on every observation phase. The machine tracks observations, thoughts, and tool results in context, enabling invariant verification across the full agent lifecycle.

`createA2AMachine()` models agent-to-agent protocol negotiation with bounded rounds. `createHITLMachine()` handles multi-approver workflows with escalation on timeout. `createSubagentMachine()` coordinates parallel task execution with configurable strategies (parallel, sequential, race).

The `RuntimeAdapter` attaches to live agents via XState subscription, EventEmitter, or callback patterns. It maintains state history and supports auto-validation on transitions.

## TLA+ specification generation

`generateTLASpec()` translates XState machines to valid TLA+ syntax. States become `CONSTANTS`, context variables become `VARIABLES`, and transitions become TLA+ actions with appropriate guards and primed variable updates. MBT invariants are translated to TLA+ formulas where possible (e.g., `budgetRespected` becomes `llmCallsUsed <= llmCallsBudget`).

The `TLCRunner` searches common paths for `tla2tools.jar` and falls back gracefully with a helpful error message when TLC isn't installed. Temporary files are created in the OS temp directory and cleaned up after verification.

## CLI and CDS integration

The CDS plugin registers `cds mbt` with subcommands for initialization, test running, machine extraction, TLA+ export, and runtime watching. `MbtService` provides programmatic access with machine/invariant discovery via glob patterns.

The `extract` command parses CDS files for `@agent` annotations and generates XState machines with HITL states for actions marked `@agent.hitl`. The `watch` command connects to a running service and validates state transitions in real-time.
