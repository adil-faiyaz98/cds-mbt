# Model-Based Testing Package for SAP CAP

A comprehensive MBT package enabling formal verification of CAP agent orchestration through XState machines, built-in invariants, and TLA+ export for external model checking.

The implementation spans six feature areas: core infrastructure with templates and CDS integration (FEAT-001), Joule agent integration with ReAct/A2A/HITL patterns (FEAT-002), TLA+ specification generation and TLC runner (FEAT-003), 225 unit tests with >80% coverage on core modules (FEAT-004), three complete example projects (FEAT-005), and documentation with CI pipeline (FEAT-006). The architecture is clean: a path exploration engine feeds into invariant checking, while separate modules handle machine extraction from CDS services and formal verification export.

**Watch for:** FEAT-001 shows status "pending" in its JSON file despite all its deliverables existing in the codebase—this is a bookkeeping gap, not a functional one (confirmed). The `extract` CLI command calls `extractFromDefinition` with a string but the function signature expects a structured definition object (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The core MBT engine uses a visitor pattern to enumerate all reachable paths through an XState machine, checking a set of invariants at each step. Loop detection and path/depth limits prevent runaway exploration. The invariant builder provides a fluent API for defining custom checks alongside eight built-in invariants covering budget, retries, completion validity, escalation reasons, and data consistency.

Joule integration provides four pre-built machine templates (ReAct, A2A, HITL, Subagent) plus extraction utilities to derive machines from `@agent`-annotated CDS services. The templates are well-structured with proper guards, actions, and context management, though the machine extractor has a type mismatch when called from the CLI.

The TLA+ export generates syntactically valid specifications with state constants, type invariants, and transition relations. The TLC runner gracefully handles missing TLC installation by returning a descriptive error rather than crashing. Context variables are mapped to TLA+ types, and common MBT invariants have explicit TLA+ translations.

All 225 tests pass across 8 test suites. Coverage on core modules ranges from 75% (machine-extractor) to 100% (invariants/index). The three example projects demonstrate real-world patterns: ETL migration with rollback, e-commerce order agent with ReAct, and multi-level approval with HITL.

### Extract command function signature mismatch

In `lib/cli/extract.js`, when the service file ends with `.cds`:

```javascript
if (servicePath.endsWith('.cds')) {
  machine = extractFromDefinition(serviceContent, { filename: servicePath });
}
```

But `extractFromDefinition` in `lib/joule/machine-extractor.js` expects:

```javascript
function extractFromDefinition(serviceDefinition) {
  const {
    name = 'agent',
    actions = [],
    hitlActions = [],
    tools = [],
    budget = 10,
    maxRetries = 3
  } = serviceDefinition;
  // ...
}
```

Passing raw file content causes destructuring to fail silently—all properties default to their fallback values, producing a generic machine that doesn't reflect the actual service definition.

### Test coverage gaps

The machine extractor has 75% coverage—the lowest among core modules. The untested paths appear to involve edge cases in annotation parsing (malformed `@agent` options, nested `@agent.hitl` annotations). These paths return default values, so failures are silent rather than exceptions.
